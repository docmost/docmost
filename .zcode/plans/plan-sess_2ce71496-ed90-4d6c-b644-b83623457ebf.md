## Plan: Add `CUSTOM_CSS_URL` env var for runtime style overrides

### Overview
Add a new `CUSTOM_CSS_URL` environment variable that, when set, injects a `<link rel="stylesheet">` tag into the app's `index.html` at server startup. This follows the exact same placeholder-replacement pattern already used for `<!--window-config-->` (env config injection) and `<!--meta-tags-->` (SEO meta tags).

### Files to change (4 files)

**1. `apps/client/index.html`** — Add a `<!--custom-css-->` placeholder comment inside `<head>`, right before `</head>` (after the `<!--meta-tags-->` line).

**2. `apps/server/src/integrations/environment/environment.service.ts`** — Add a `getCustomCssUrl()` method:
```ts
getCustomCssUrl(): string {
  return this.configService.get<string>('CUSTOM_CSS_URL');
}
```

**3. `apps/server/src/integrations/environment/environment.validation.ts`** — Add an optional, URL-validated field:
```ts
@IsOptional()
@IsUrl({ protocols: ['http', 'https'], require_tld: false })
CUSTOM_CSS_URL: string;
```

**4. `apps/server/src/integrations/static/static.module.ts`** — In `onModuleInit()`, after the existing `window-config` replacement, also replace `<!--custom-css-->` with a `<link>` tag (or empty string if unset):
```ts
const customCssUrl = this.environmentService.getCustomCssUrl();
const customCssTag = customCssUrl
  ? `<link rel="stylesheet" href="${customCssUrl}" />`
  : '';
const transformedHtml = html
  .replace(windowVar, windowScriptContent)
  .replace('<!--custom-css-->', customCssTag);
```

**5. `.env.example`** — Document the new variable:
```
# URL to a custom CSS stylesheet for overriding fonts, colors, and theme styles.
# Example: https://cdn.example.com/custom-theme.css
# Or mount a file into the container and use a local path: /custom-theme.css
CUSTOM_CSS_URL=
```

### How it works at runtime
1. At server startup, `StaticModule.onModuleInit()` reads `index-template.html`, replaces `<!--custom-css-->` with a `<link>` tag (if `CUSTOM_CSS_URL` is set), replaces `<!--window-config-->` with the config script, and writes the result to `index.html`.
2. The share-SEO controller reads the already-processed `index.html`, so the `<link>` tag is present on shared pages too — no changes needed there.
3. In Docker, users can either point to a remote URL or bind-mount a CSS file into `/app/apps/client/dist/` and reference it as a local path (e.g., `CUSTOM_CSS_URL=/custom-theme.css`), since `@fastify/static` already serves from that directory.

### Why this approach
- **Follows existing patterns**: Uses the same placeholder-replacement mechanism as `<!--window-config-->` and `<!--meta-tags-->`.
- **Minimal change**: ~15 lines across 4 files.
- **Maintainable**: No build step changes, no client-side code changes, survives upstream merges cleanly.
- **Flexible**: Works with remote URLs, CDN-hosted CSS, or locally mounted files in Docker.
